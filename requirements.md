# Payroll Manager

## Цель

Автоматизировать процесс выдачи заработной платы сотрудникам.

## Основные проблемы

- Зарплата поступает частями.
- Нужно самостоятельно выбирать очередность выдачи.
- Возможны частичные выплаты.
- Можно забыть отметить выдачу.
- Нужно знать остаток денег.
- Руководитель хочет видеть прогресс.
- Возможны внеплановые (форс-мажорные) расходы денежных средств.
- Иногда часть зарплаты может быть выдана другим пользователем системы без участия основного пользователя.

## Основные сущности системы

### Department

Сущность представляет подразделение компании, сотрудники которого участвуют в зарплатном учете.

Поля:

- id
- name
- type

### User

Сущность представляет пользователя системы, который может выполнять операции или просматривать информацию.

Поля:

- id
- name
- role

### Employee

Сотрудник компании, участвующий в зарплатном учете.

Поля:

- id
- fullName

### EmployeeAssignment

Сущность представляет связь сотрудника с конкретным подразделением и содержит информацию о его работе в данном подразделении.

Один сотрудник может иметь несколько назначений в разных подразделениях и выполнять разные должности с разным размером заработной платы.

Поля:

- id
- employee
- department
- position
- salary

### SalaryPeriod

Период, за который производится выплата заработной платы.

Поля:

- id
- month
- year

Для месяца используется `java.time.Month`.

### SalaryPlan

Сущность хранит планируемую сумму выплаты для подразделения за конкретный период.

Поля:

- id
- department
- period
- amount

Для обычных участков планируется общая сумма выплаты подразделению.

Программа не требует от основного пользователя указывать, как начальник участка распределил полученную сумму между своими сотрудниками.

### CashOperation

Сущность хранит все движения наличных денежных средств.

Поля:

- id
- date
- amount
- type
- comment
- performedBy

Используется для учета:

- получения денег;
- выдачи денег;
- внеплановых расходов;
- других движений денежных средств.

### Payment

Сущность отслеживает конкретную выплату.

Поля:

- id
- salaryPlan
- employee
- amount
- date
- performedBy
- comment

`employee` может отсутствовать, если деньги выдаются подразделению целиком.

Для АДС и АУП должна существовать возможность указать конкретного сотрудника, которому была выдана заработная плата.

## Особенности учета подразделений

В системе существуют подразделения различных типов:

- участки;
- стройучасток;
- «Фаворит»;
- АДС;
- АУП;
- сварщики;
- котельщики;
- другие подразделения.

Для обычных участков основному пользователю не требуется вручную распределять полученную сумму между сотрудниками.

Например:

Общая сумма участка:

- 660 000

Выдано:

- 200 000

Остаток:

- 460 000

При необходимости основной пользователь может указать конкретного сотрудника участка и зафиксировать отдельную выплату ему.

Такая выплата должна учитываться в остатке суммы, необходимой подразделению.

Для АДС и АУП выплаты обычно производятся непосредственно конкретным сотрудникам.

## Движение денежных средств

Главный экран должен показывать основные показатели:

- общую сумму, которую необходимо выплатить;
- общую сумму уже выданных денег;
- остаток задолженности;
- текущую сумму денег на руках.

Пример:

Необходимо выплатить:

1 000 000

Получено:

600 000

Выдано:

- участок №1 — 200 000
- участок №2 — 240 000

Денег осталось на руках:

160 000

Эти 160 000 должны учитываться как деньги, которые уже получены и будут использованы для дальнейших выплат.

## Внеплановые расходы

Возможны форс-мажорные расходы, которые не были предусмотрены первоначальным распределением денег.

Например:

- закупка товара снабженцем;
- аварийная ситуация;
- срочная выплата экскаваторщику;
- другие непредвиденные расходы.

Такие операции должны фиксироваться отдельно и уменьшать текущий остаток денежных средств.

Для каждой такой операции необходимо сохранять:

- сумму;
- дату;
- комментарий;
- пользователя, выполнившего операцию.

## Бизнес-правила

- Нельзя выдать заработную плату одному человеку больше одного раза за месяц.
- Исключение — авансовые выплаты.
- Каждая операция выдачи должна сохраняться в истории.
- Каждая операция движения денежных средств должна сохраняться в истории.
- Остаток денежных средств должен рассчитываться автоматически.
- Остаток по подразделению должен рассчитываться автоматически.
- При выплате конкретному сотруднику сумма должна учитываться в общей сумме выплат соответствующего подразделения.
- Пользователь должен иметь возможность вручную выбрать сумму выплаты подразделению.
- Пользователь должен иметь возможность увеличить или уменьшить планируемую сумму подразделения.
- Зарплаты сотрудников могут изменяться, поэтому суммы не должны быть жестко зашиты в программу.
- Один сотрудник может работать в нескольких подразделениях.
- Один сотрудник может иметь разные должности и разные суммы заработной платы в разных подразделениях.
- Пользователь, выполняющий выплату, должен фиксироваться в истории операции.
- Заместитель директора может выполнять отдельные выплаты без участия основного пользователя.
- Выплаты, выполненные другим пользователем, не должны искусственно увеличивать сумму наличных денег, находящихся на руках у основного пользователя.

## Роли пользователей

### Пользователь, выполняющий операции

Может:

- получать и учитывать деньги;
- создавать операции движения денежных средств;
- выполнять выплаты;
- указывать сумму выплаты;
- фиксировать выплаты конкретным сотрудникам;
- создавать внеплановые расходы;
- просматривать историю операций.

### Руководитель

Может:

- просматривать состояние выплат;
- контролировать общий прогресс;
- видеть суммы полученных и выданных денег;
- видеть остатки;
- просматривать историю операций.

Доступ руководителя — `read only`.

### Другие пользователи

Могут иметь ограниченный доступ в соответствии со своей ролью.

## Главный экран

На главном экране необходимо показывать только основные показатели:

- Всего необходимо выплатить
- Всего выдано
- Осталось выдать
- Денег на руках

Дополнительная информация, например:

- кто выполнил выплату;
- комментарии;
- история операций;

не должна перегружать главный экран и должна быть доступна в соответствующих разделах системы.

## История операций

Все операции должны сохраняться и быть доступны для просмотра.

Для операции необходимо знать:

- дату;
- сумму;
- тип операции;
- пользователя;
- комментарий.
